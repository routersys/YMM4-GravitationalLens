# 重力レンズ for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-GravitationalLens.svg)](https://github.com/routersys/YMM4-GravitationalLens/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、ブラックホールの近くにいるカメラが遠くの空を見る様子を、シュワルツシルト時空での光の経路から求めて映像に描く映像エフェクトプラグインです。
画素ごとに、その画素へ届く光が空のどこから来たかを求め、その場所の色を取り出します。
履歴フレーム、参照画像、学習済みモデルを使わず、入力された一枚の映像だけを処理します。
結果は設定と画素の位置から決定論的に決まり、同じ設定では常に同じ絵になります。
強さ、位置X、位置Y、距離、画角の5項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「重力レンズ」として表示されます。カテゴリは加工です。

ブラックホールのそばを通る光は、強く曲がります。その結果、遠くの星はブラックホールのまわりで引き伸ばされた弧や環に見え、ブラックホールの方向には光の届かない黒い円が現れます。この黒い円がシャドウです。環のうち、光源がブラックホールの真後ろにあるときに見えるものがアインシュタインリングです。本プラグインは入力された映像を遠くの空を写した一枚の絵として扱い、ブラックホールの近くにいるカメラが同じ空を見たときの絵を作ります。

画素ごとの処理は次の順で進みます。

1. 画素が見ている方向と、ブラックホールの方向とのなす角を求めます。
2. その角から、その画素に届いた光が遠くの空のどの方向から来たかを、表から読みます。
3. その方向にあたる場所の色を、入力映像から取り出します。

表はシュワルツシルト時空の光の経路を楕円積分で解いて作ります。シュワルツシルト時空は回転しない球形のブラックホールの外側の時空です。ブラックホールまでの距離はシュワルツシルト半径の何倍かで指定します。シュワルツシルト半径は事象の地平線の半径です。

本プラグインが依拠する資料は次のとおりです。

- 光線がブラックホールの近くのカメラから遠くの空へ達するまでの追跡: James, von Tunzelmann, Franklin and Thorneの論文「Gravitational lensing by spinning black holes in astrophysics, and in the movie Interstellar」（Classical and Quantum Gravity、2015年）が示した、近くのカメラから遠くの空へ光線をたどる考え方を参照しています。この論文は回転するブラックホールを扱い、本プラグインは回転しないブラックホールを扱います。
- 楕円積分の計算: Carlsonの論文「Numerical computation of real or complex elliptic integrals」（Numerical Algorithms、1995年）が示した、対称形の楕円積分R_Fの計算法に基づきます。
- アインシュタインリングの大きさ: Einsteinの論文「Lens-like action of a star by the deviation of light in the gravitational field」（Science、1936年）が示した、レンズ天体の真後ろの光源が環に見える角度の式との一致を、試験で確かめています。
- 光子球の付近の偏向角: Bozzaの論文「Gravitational lensing in the strong field limit」（Physical Review D、2002年）が示した、光子球の付近での偏向角の漸近式との一致を、試験で確かめています。

結果は設定と画素の位置だけから決まります。時間値と乱数は使いません。同じフレームは何度描いても同じ結果になります。

処理はDirect2Dのカスタムピクセルシェーダーが行います。角度の表はCPUで求め、シェーダーへ画像として渡します。CPUへの画素の読み戻しは行いません。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-GravitationalLens/releases/latest)ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4を起動し、タイムライン上のアイテムに映像エフェクトを追加します。
4. 映像エフェクトの種類として「重力レンズ」を選択してください。

## 主な機能

### 1. 見える方向とブラックホールの位置

カメラはレンズのゆがみがない透視投影として扱います。処理する範囲は、このエフェクトに入る映像を囲む矩形です。「画角」は処理する範囲の横幅に対する水平方向の画角で、その中心がカメラの向く方向です。

ブラックホールは処理する範囲の中心から「位置X」だけ右、「位置Y」だけ下にずれた画素の方向にあります。単位は画素です。画素が見ている方向と、ブラックホールの方向とのなす角をψとします。ψが0のとき、画素はブラックホールの方向をまっすぐ見ています。

### 2. シュワルツシルト時空での光の経路

長さの単位はシュワルツシルト半径にそろえます。ブラックホールの中心からの距離をr、u = 1/rとし、ブラックホールまでの距離をDとします。

光の経路は、遠くで光が進む直線と中心との最短距離bで決まります。このbが衝突係数です。光が中心のまわりを回る角度をφとすると、経路は次の式を満たします。

```
(du/dφ)² = 1/b² − u² + u³
```

距離Dに止まっているカメラが測る、画素の方向とブラックホールの方向とのなす角ψと、衝突係数bは次の式で結ばれます。

```
sin ψ = (b / D) √(1 − 1/D)
```

衝突係数が小さいと、光は経路の途中でブラックホールへ落ち込みます。落ち込まずに離れていける最小の衝突係数は、次の値です。

```
b_c = 3√3 / 2 ≈ 2.598
```

b_cは、光が円軌道を描ける球面である光子球にある、円軌道の光の衝突係数です。光子球の半径は1.5です。ブラックホールの方向に近い画素へ届いた光を逆向きにたどると、遠くの空へ達せず、ブラックホールへ落ち込みます。この画素には、遠くの空から来た光が届かないため、黒くなります。この範囲がシャドウです。シャドウの見かけの半径ψ_shは次の式です。

```
sin ψ_sh = (b_c / D) √(1 − 1/D)
```

ψがψ_sh以下の画素は、不透明な黒にします。Dが大きいほど、シャドウは小さくなります。

### 3. 光の来た方向

画素へ届いた光を逆向きにたどり、遠くの空へ達するまでに光がブラックホールのまわりを回る角度をΦとします。光が曲がらないときは、Φ = π − ψです。曲がるときは、Φがこれより大きくなります。画素に届いた光が来た空の方向は、ブラックホールの方向から測って、次の角度Θの位置にあります。

```
Θ = π − Φ
```

曲がらないときは、Θ = ψです。曲がるとΘはψより小さくなり、Φが大きいと負にもなります。負のΘはブラックホールの方向から見て画素と反対の側を表します。

b > b_cの光のΦは次の式で求めます。u³ − u² + 1/b² = 0の3つの実数の解のうち、小さい正の解をu₁、大きい正の解をu₂、負の解をu₃とします。

```
m = (u₁ − u₃) / (u₂ − u₃)
sin²φ(u) = (u₂ − u₃)(u₁ − u) / ((u₁ − u₃)(u₂ − u))
Φ = 2 / √(u₂ − u₃) × [ F(φ(0), m) + σ F(φ(1/D), m) ]
```

Fは第1種の不完全楕円積分で、Carlsonの対称形の楕円積分R_Fで計算します。σは、ψがπ/2より小さいとき+1、π/2以上のとき−1です。ψがπ/2より小さいと、光は画素へ届く前にいったんブラックホールへ近づく向きに進んでいるため、符号が変わります。

衝突係数がb_c以下でも、ψがπ/2以上の光は、ブラックホールから遠ざかる向きに進んでいます。この光には折り返す点が無く、Φは1/b² − u² + u³の平方根の逆数を0から1/Dまで積分した値です。48点のガウス・ルジャンドル求積で求めます。

### 4. 角度の表

Θを画素ごとに計算すると重いため、ψに対するΘを表にして、画素ごとに読みます。表の幅は2048個です。

表の位置はψ − ψ_shの自然対数で決めます。範囲は、ψ − ψ_shが10⁻⁷ラジアンの位置から、πからψ_shを引いた値までです。シャドウの縁に近いほど、光はブラックホールのまわりを何周もして届くため、Θは対数に比例して大きく変わります。対数で等間隔に並べると、この変わり方がほぼ直線になり、線形補間で十分になります。

表の値は32ビットの浮動小数点数で、Θを2πで折り返さずに持ちます。シェーダーは読んだΘを−πからπの範囲へ折り返します。

「距離」を変えると、表を計算し直します。距離が同じ間は、表を再利用します。

### 5. 色の取り出しと映像の外側

画素の方向をv、ブラックホールの方向をwとします。画素に届いた光が来た空の方向sは、次の式で求めます。Θ'は、Θを−πからπの範囲へ折り返した値です。

```
s = ( sin(ψ − Θ') w + sin(Θ') v ) / sin ψ
```

sはwからvの側へΘ'だけ回した向きです。Θ'が負のときは、wから見てvと反対の側へ回した向きです。sを透視投影で映像の上の位置に戻し、その位置の色を入力映像から読みます。

入力映像は、カメラが写した遠くの空の一部にすぎません。sが映像の範囲の外にある場合や、カメラの後ろにある場合は、映像の端の色を使います。ブラックホールの近くでは、光が範囲の外から来ることが多く、端の色が筋のように伸びて見えます。

### 6. 縁の滑らかさ

1画素の範囲から来る光は、ブラックホールの近くでは入力映像の広い範囲に及びます。1点だけ読むと、細かい模様がちらつきます。そこで、出力の1画素が入力映像の上で占める広さを見積もり、広いときは複数の点を読んで平均します。

広さはψに対するΘの傾きの大きさとsin Θ' / sin ψの大きい方の値で、出力の1画素あたりの入力映像の画素の数を表します。

| 広さ | 読む点の数 | 点の並び |
|---|---:|---|
| 1.5以下 | 1 | 画素の中心 |
| 1.5を超え4以下 | 4 | 縦2×横2 |
| 4を超える | 16 | 縦4×横4 |

シャドウの縁から1.5画素以内の画素も、16点を読みます。縁の黒と外側の色が、滑らかにつながります。

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- Direct2Dのカスタムエフェクトを作成できない場合は、エフェクトを適用せず入力映像を表示します。
- 回転せず電荷を持たない、球形のブラックホールだけを扱います。ブラックホールの外側の時空はシュワルツシルト時空です。降着円盤、重力による色のずれ、ドップラー効果、光の強さの変化は扱いません。光の経路だけで、映像の色を動かします。
- カメラはブラックホールに対して静止しているものとして扱います。ブラックホールまでの距離はシュワルツシルト半径の3倍から1000倍までで、3倍より近い距離は扱いません。
- 入力映像は遠くの空の一部とみなします。映像の範囲の外から来る光と、カメラの後ろから来る光は、映像の端の色で代わりにします。
- 距離が近いと、シャドウの縁の近くで光が何周もしてから届くため、1画素の中に非常に細かい模様が入ります。この模様は最大16点を読む平均で描き切れません。表の最も内側はψ − ψ_shが10⁻⁷ラジアンの位置で、これより内側の画素にはこの位置の値を使います。
- 映像の色はsRGBの値のまま混ぜます。平均と補間は、ガンマ補正を取り除かずに行います。
- 光の経路の計算は次の方法で確かめています。
  - 光の曲がる角度が、弱い重力場の4項の展開式と、b = 200とb = 1000で1.0×10⁻⁸ラジアン以内で一致します。
  - 光子球の付近の偏向角がBozzaの漸近式へ近づきます。衝突係数の臨界値からの超過分の割合をεとして、ε = 10⁻⁴、10⁻⁶、10⁻⁸のそれぞれで、差が 40ε|ln ε| + 1.0×10⁻⁶ ラジアン以内に収まることを確かめています。
  - 楕円積分で求めた折り返す光の角度が、別に書いたシンプソン法の数値積分と、1.0×10⁻⁹ラジアン以内で一致します。距離は3倍から1000倍まで、衝突係数は臨界値の1.2倍以上で確かめています。
  - 距離が1000倍と10000倍のとき、アインシュタインリングの角度が数値積分の結果と、相対で1.0×10⁻⁹以内で一致します。距離が10⁸倍のとき、弱い重力場の展開式と相対で1.0×10⁻⁷以内で一致します。距離がDのとき、角度はEinsteinの式の√(2/D)に近づきます。差は、距離が1000倍で相対3.6%以内、10⁶倍で0.11%以内です。
  - 表を引き直した値との差は、距離が3倍、12倍、250倍、1000倍のとき、最大でも2.7×10⁻⁵ラジアンです。
- 角度の表を引くときの精度は、32ビットの浮動小数点数とGPUの三角関数の精度で決まります。試験では128×96画素の描画のうち、CPUで書いた同じ式の描画と1チャンネルあたり3を超えて違う画素が、81個以下であることを確かめています。

## 注意事項

- 処理負荷: 画素ごとに、角度の表を2回と入力映像を読みます。出力の1画素が入力映像の広い範囲に及ぶ画素は、複数の点を読むため重くなります。ブラックホールの近くやシャドウの縁の近くが、これにあたります。「距離」を変えると、角度の表をCPUで計算し直します。「距離」をアニメーションで動かすと、フレームごとに計算をやり直すため、CPUの負荷が増えます。「位置X」「位置Y」「画角」と「強さ」は、シェーダーの定数を変えるだけです。
- 強さ0%: 強さが0%のときは、表の計算も合成も行わず、映像をそのまま通します。
- 再現性: 結果は設定と画素の位置だけから決まります。時間値と乱数は使いません。同じフレームは何度描いても同じ結果になります。
- 透明部分: シャドウは不透明な黒です。シャドウの外側の画素は、光が来た場所の色と不透明度になります。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。YMM4が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、破棄するときと、Direct2Dがシェーダーの定数を書き込むときに起きた例外を報告し、その後はYMM4へそのまま渡します。更新の確認では、更新情報の取得と比較で起きた例外は報告しません。通知の文を組み立てて表示するときに起きた例外は報告し、YMM4へは渡しません。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | Direct2Dのカスタムエフェクトを作成できないときに、エフェクトを適用せず入力映像を表示したとき |
| 更新の確認の通信の失敗 | manjubox.netとGitHubのどちらへも接続できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避します。次にYMM4を起動したあと、本プラグインのエフェクトを生成するか、同じくYMM4-Telemetryで報告する別のプラグインが動き始めると、退避した報告を1回の起動で10件まで送り直します。送信も再送も非同期に行うため、通信を待って起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
